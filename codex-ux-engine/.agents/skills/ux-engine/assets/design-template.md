# Project design notes - optional starter

This file is a template, not UX Engine policy or an adopted project design system. Use it only when creating requested project design documentation. Adapt sections from observed conventions and explicit product decisions; leave unknown choices identified as unknown rather than inventing rules. Existing project instructions and design documentation take precedence.

## Users and tasks

Record primary users, frequent tasks, device contexts, and information that must remain visible or easy to compare. Describe whether the product favors compact operational density, guided occasional use, or distinct layouts for each.

## Visual language

Record existing brand character and its source. Identify actual typography roles, spacing scale, surfaces, color tokens, icon conventions, and reusable component locations. Document established choices rather than imposing a modern/minimal/mobile-first style.

## Actions and status

Describe the primary/secondary action hierarchy and semantic status conventions. Pair critical color cues with text or another accessible indicator. Preserve existing destructive-action confirmation and recovery rules unless changes are requested.

## Forms and data

Record grouping, label/error conventions, defaults, validation ownership, and unsaved-work handling. Describe which fields support the main task and when disclosure or detail views are appropriate. Document table comparison needs, filters, selection, actions, and mobile behavior.

## Accessibility and motion

Record the project's accessibility target and component conventions: focus, keyboard interaction, dialog behavior, announcements, zoom/reflow, contrast, and reduced motion. Distinguish adopted requirements from checks still needed.

## Reusable decisions

For each new reusable rule, record its rationale, affected components, and verification evidence. Update only decisions established by requested work. Do not convert one screen's exception into a project-wide rule.
