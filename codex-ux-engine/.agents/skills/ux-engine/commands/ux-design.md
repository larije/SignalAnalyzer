# UX DESIGN

Design the requested screen or interaction using the shared context and boundaries in SKILL.md. Read the verification reference for relevant states and accessibility acceptance conditions; consult design principles for tradeoffs.

Produce a design proportional to the task:

1. User, primary task, existing constraints, and material assumptions.
2. Primary action, information hierarchy, grouping, navigation, and interaction flow.
3. Reused components and any necessary additions.
4. Relevant states, validation, feedback, and recovery behavior.
5. Responsive behavior that supports the task, including comparison or frequent keyboard use where relevant.
6. Accessibility acceptance conditions and a practical implementation/verification plan.

For a design-only request, stop at the proposed design. When implementation is part of the request, proceed within that authorization; do not require another approval solely because this mode includes design. If a missing business rule blocks implementation, ask that specific question and continue independent work.

Implement with existing components and conventions, preserve unrelated behavior, and run applicable checks. Report what changed and which checks were actually performed. Do not label a proposed state matrix as verified behavior.
