# UX REVIEW

Give a concise critique of the requested screen. Keep it read-only unless the user also requests changes. Use the shared boundaries and design-principles reference in SKILL.md.

Start with the primary task and what evidence was available. Focus on the few issues that matter most; a punchy title is optional, concrete reasoning is required.

For each issue use:

**Location/evidence -> Observation -> Why -> Fix -> Expected effect -> How to check**

Distinguish what was observed from what is inferred. Present expected benefits as hypotheses, not proven improvements. Mark behavior not inspected as not tested.

Preserve successful patterns and explain tradeoffs when recommendations affect density, comparison, disclosure, or mobile workflows. End with the most useful next change and any material verification limit. Avoid numeric scores unless explicitly requested with a stated rubric.
